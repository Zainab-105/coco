## Stack

| Layer | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router, React 19, TypeScript) |
| Admin panel / backend | Payload CMS 3 running inside the same Next.js app |
| Database | PostgreSQL 17 |
| Styling | Tailwind CSS 4 with COCO brand tokens |
| Media | Cloudflare R2 (S3-compatible) in production, local disk in dev |
| Tests | Vitest (unit + integration), Playwright (e2e) |

One codebase, one deployment, one database: the storefront and admin share the same data, so every order, customer and stock change appears in the admin instantly.

## Getting started

Requirements: **Node.js 24.22+** (or 22.23+) and npm. No Docker or system Postgres needed.

```bash
cp .env.example .env          # then set PAYLOAD_SECRET
npm install
npm run db:dev                # terminal 1: project-local Postgres 17 on port 5433 (coco + coco_test)
npm run dev                   # terminal 2: http://localhost:3000, admin at /admin
npm run seed:sample           # sample catalogue, banners, coupons and 40 demo orders
```

On first visit to `/admin`, create the owner account. Environments, migrations, R2 and backups:
[`docs/ops/DEPLOYMENT.md`](docs/ops/DEPLOYMENT.md).

## Admin operations

| Task | Where |
| --- | --- |
| Work queue (new orders, payments to verify, to ship, abandoned carts, low stock) and last-30-days KPIs | Admin dashboard |
| Sales, customer, marketing, finance and inventory reports with date presets, custom range and comparison | Reports (`/admin/reports`); each table has "Download CSV" |
| Record ads, packaging, courier bills (used in estimated profit) | Reports > Expenses |
| Follow up an abandoned checkout | Marketing > Abandoned carts > open one > "WhatsApp" / "Mark contacted" |
| Newsletter list (export includes each person's unsubscribe link) | Marketing > Subscribers > "Export CSV" |
| Moderate reviews | Reviews: status tabs show the queue; open one > "Approve" / "Hide" / "Spam". Approving makes its photos and videos public |
| Answer complaints and messages from `/contact` | Support Tickets: status tabs, "WhatsApp" / "Email" on the ticket, resolution notes |
| Turn on two-factor authentication | Security (2FA) in the side menu |
| Keep an old address working | Marketing > Redirects. Added automatically when a product or category URL changes |
| Disable a customer login | Customer Accounts > tick "Disabled" |
| Schedule a banner or sale | Marketing > Banners: set start/end; the Schedule column shows Live / Scheduled / Ended |
| Filter orders by status | Status tabs above the Orders list |
| Confirm / pack / ship / deliver / cancel an order | Buttons at the top of an order (shipping asks for the tracking number) |
| Invoices and packing slips | Order screen, or tick several orders in the list and use "Print invoices" / "Packing slips" |
| Export to Excel | "Export CSV" above Orders, Customers or Products (respects the current filters; cost columns for managers/owner only) |
| Restock, damage, stock count correction | Inventory Adjustments > Create (variant products need the variant SKU) |
| Bulk price and stock update | Products > "Bulk update prices & stock" (export, edit, upload, preview, apply) |
| Merge duplicate customers | Customer screen > "Merge duplicate" |

Every export (including report downloads), merge and admin edit is recorded in Activity Logs (owner only).

Report definitions: **net sales** = item value after discounts of orders that are not cancelled, returned or refunded;
**estimated profit** = net sales + delivery and gift-wrap charges - cost of goods (snapshot on each order line) - recorded expenses.
Days are Pakistan time. Staff see sales and marketing reports; Finance and Inventory (cost, profit, stock value) need manager or owner.
Figures are reconciled against raw SQL in `tests/int/reports.int.spec.ts`.

## Conventions

- All money is stored as whole PKR integers.
- Phone numbers are normalised to `+923XXXXXXXXX`; this is how guest orders are matched to one customer profile.
- Order totals are always recomputed on the server (`computeTotals` hook); client-submitted totals are never trusted.
- Checkout re-prices the cart from the database inside a transaction that locks the products being bought, so the last unit cannot be sold twice.
- Customer order pages require the order's private token (or the checkout phone number on Track order); order numbers alone reveal nothing.
- Stock changes are written to the append-only `inventory-adjustments` ledger.
- Customer files go to `customer-uploads`, never `media`: private until a review using them is approved, with file type checked from content and random filenames.
- A new third-party script, image host or form target must be added to the CSP in `lib/security/headers.ts`, or browsers block it.
- Customers are not Payload auth users, so a customer can never become `req.user`. Sessions are a signed cookie (`lib/account`); order history is orders placed with the verified email.
- Payment is only marked **Paid** after gateway callback or manual verification in the merchant portal. Screenshots are evidence, never confirmation.
- UI components take view models (`components/product/types.ts`), not raw Payload docs; map in `lib/storefront/mappers.ts`.
- Client components must not import `lib/storefront/catalog.ts` or `data.ts` (marked `server-only`); pure helpers live in `filters.ts`.
- Storefront pages use ISR (5 min) plus on-demand `revalidatePath` from Payload hooks, so admin edits show on the next visit.
- `public/mock/` holds design-review crops of the brand boards. Delete it (and its `next.config.ts` image pattern) once real product media is uploaded.
